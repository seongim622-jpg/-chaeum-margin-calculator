# 채움크리에이티브 상품 마진 계산기

의존성 없는 정적 웹앱. Chrome, Edge, Safari 등 최신 브라우저에서 사용합니다.

## 실행 / 배포

- 개발: 폴더에서 `python -m http.server 8000` 실행 후 `http://localhost:8000` 접속 (ES Modules이므로 `file://` 직접 열기는 권장하지 않습니다).
- 테스트: `node --test calculator.test.mjs` (Node 18 이상 권장).
- GitHub Pages: 폴더의 파일을 GitHub 저장소 루트에 업로드 → Settings → Pages → Deploy from a branch → main / (root) → Save. 정적 호스팅에 백엔드가 필요 없습니다.

## 계산 원칙

- 상품 판매가 `P`, 구매자 배송비 `B`(주문당 수취 배송비 ÷ 주문당 수량), `F`=매입원가+포장비+판매자 배송비+기타비용+원화 고정 광고비(주문당 비용은 주문당 수량으로 나눔).
- 플랫폼 수수료, 별도 카드 수수료, 매출 연동 광고비, **사용자 설정 예상 세금 적립률**의 합을 `R`라 함. 카드 수수료 포함 체크 시 카드 수수료를 다시 부과하지 않음.
- 구매자 배송비도 수수료 대상인 경우 그에 해당하는 추가 수수료를 `S`라 함.
- 매출액: `P+B`; 총비용: `F+P×R+S`; 예상 이익: `P+B−F−P×R−S`.
- 손익분기 판매가: `max(0,(F−B+S)/(1−R))`.
- 목표 이익률은 **총매출(P+B) 대비**로 정의합니다. 따라서 목표 마진 `M` 판매가: `max(0,(F−B+S+M×B)/(1−R−M))`. 위 수식은 구매자 배송비 수입이 있을 경우 정확한 총매출 기준 마진을 달성합니다.
- 목표 달성 불가(분모 ≤ 0)면 가격 계산 불가 메시지.
- 상품 원가 부가세 포함 체크는 정보를 보관하기 위한 것입니다. 세무상 공제 가능성 확인 없이 매입가를 임의로 세전 환산하지 않습니다.
- 실제 납부 부가세 및 소득세는 산출하지 않습니다. 예상 세금 적립액은 회계상 세액이 아니라 내부 보수적 자금 적립입니다.
- 플랫폼 수수료율은 사용자 입력 전까지 공란이며 미설정 항목을 0%로 가정한 결과는 경고합니다. 플랫폼 비교에서는 미설정 플랫폼을 제외합니다.
- 동일 플랫폼의 여러 카테고리 수수료가 필요하면 플랫폼 설정을 다시 입력하여 개별 상품으로 저장할 수 있습니다. 현재 구조에서는 플랫폼마다 기본 수수료 설정이 하나이며, 저장 상품은 공통 최신 플랫폼 설정을 참조합니다.
- 상품 수량 및 주문당 상품 수량은 독립적으로 입력합니다. 수량이 주문당 수량의 배수가 아니어도 비용은 단위당 평균 추정으로 계산합니다.

## 보관 / 보안

- 모든 자료는 현재 브라우저의 localStorage에만 저장되며 다른 기기와 동기화되지 않습니다.
- JSON 전체 백업(현재 입력값, 플랫폼 설정, 상품 및 이력 포함), CSV 상품 내보내기·가져오기를 지원합니다.
- 브라우저 사이트 데이터 삭제·시크릿 모드 사용 시 저장 내용이 사라질 수 있으므로 백업을 권장합니다.
